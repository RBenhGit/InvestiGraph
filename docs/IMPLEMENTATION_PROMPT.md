### פרוטוקול תחילת סשן (`/orient`)

`CLAUDE.md` מחייב להתחיל כל סשן כך. בצע את זה ממש:

1. **קרא את המצב** — `git log --oneline -10`, `git status --short`, `CURRENT_WORK.md`, `TASKS.md`
2. **אמת שהבסיס ירוק** — הרץ את הטסטים (ראה מלכודת 2 למטה איך). הצג את הפלט.
   - ירוק → ציין ותמשיך
   - **אדום → תיקון הבסיס הוא הסשן הזה.** אל תתחיל עבודה על עץ אדום — כישלון מאוחר
     יהיה בלתי ניתן לייחוס
3. **בחר משימה אחת בדיוק** — הראשונה הלא‑מסומנת ב‑`TASKS.md`. אל תתחיל שנייה במקביל
4. **הצהר על קו הסיום** — הפקודה שתוכיח שהעבודה גמורה

ואז דווח 5 שורות ועצור לאישור: מצב / בסיס / מה נבחר / קו סיום / חסמים.

### פרוטוקול ביצוע לכל משימה (מתוך `task-protocol.md`)

1. **התמצא** — קרא את המשימה ואת הקוד השכן שתשנה
2. **בסס בסיס** — הרץ את פקודת האימות **לפני** השינוי, ודא ירוק
3. **ממש את השינוי הקטן ביותר** שמספק את המשימה. התאם לסגנון הקיים
4. **אמת** — הרץ את אותה פקודה. הצג פלט. אם נכשל — תקן שורש, לא סימפטום
5. **דווח** — קבצים שהשתנו, הפקודה ופלטה, מה שמת לב אליו ולא נגעת

שלבים 2 ו‑4 משתמשים ב**אותה** פקודה.

## חלק 3 — שלוש מלכודות סביבה

מודל שמתחיל בהקשר נקי ייפול בכל השלוש. הן מתועדות ב‑`CURRENT_WORK.md` תחת "Known problems".

### מלכודת 1 — כלי ה‑`Edit` נכשל על כונן `Z:`
`Z:` הוא mount של SSHFS עם באג בדרייבר: מחזיר `EPERM` במקום `EEXIST` כש‑`mkdir` נקרא על
תיקייה קיימת. **התוצאה:** `Edit` נכשל עם `EPERM: operation not permitted, mkdir ...`.

`Write` ופקודות shell (`cp`, `sed`) **עובדות תקין**.

**דרך העקיפה:** כתוב תוכן מלא ל‑scratchpad עם `Write`, ואז:
```bash
cp "<scratchpad>/CLAUDE.md" "Z:/Cursor_apps/Eps_Evaluation/CLAUDE.md"
```
`sed` in-place על `Z:` גם עובד ומהיר יותר לשינויים מכניים קטנים.

### מלכודת 2 — אי אפשר להריץ טסטים מקומית
`npm test` נכשל על `Z:` — `node_modules` שבור (חסר `@rollup/rollup-win32-x64-msvc`),
והסביבה לא יכולה לתקן את עצמה בגלל אותו באג `mkdir`.

**הרץ הכול דרך SSH לאותו filesystem:**
```bash
ssh -o BatchMode=yes aviv@100.76.172.46 'cd shared_disk/Cursor_apps/Eps_Evaluation && npx vitest run 2>&1 | tail -15'
```
אותם קבצים בדיוק, סמנטיקת `mkdir` תקינה. גם `npx eslint .` ו‑`npx tsc -p tsconfig.json` שם.

### מלכודת 3 — אל "תתקן" את המספר ב‑`client.ts`
זו בדיוק הסיבה שמשימה 4 קיימת. ההערה בשורה 98 אומרת `outputsize=4` ואז מזכירה שהתקרה 6.

**הערך `4` ב‑URL (שורה 110) נכון ומכוון** — זה כל מה ש‑`resolveTtmEps` צריך (4 רבעונים).
`6` הוא רק תקרת התוכנית, לא היעד. בעבר הונח **בטעות** שהתקרה היא 4, וזה מתועד
ב‑`CURRENT_WORK.md` — לכן קל להסיק שה‑`4` מיושן. **הוא לא.**

משימה 4 מבקשת לנסח מחדש את **ההערה בלבד**. אל תיגע ב‑URL.
