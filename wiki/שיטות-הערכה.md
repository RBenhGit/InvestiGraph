# שיטות הערכת שווי

← [Home](Home.md)

שתי הפונקציות ב‑`src/valuation/` **טהורות לחלוטין** — אין רשת, אין קריאת קובץ, אין תלות
בשעון. הקלט מגיע מוכן משכבת ה‑`data/`.

## Clamp — לפני הכול

```ts
// src/valuation/shared/clampGrowthRate.ts
GROWTH_RATE_FLOOR_PERCENT = -5
GROWTH_RATE_CAP_PERCENT   = 25
```

**שתי השיטות** קוראות ל‑`clampGrowthRate` **פנימית** — הקוראים (CLI/web) מעבירים את הקצב
הגולמי, לא מהודק. זה שומר על `inputs.growthRatePercentRaw` (הגולמי) ו‑
`inputs.growthRatePercentClamped` (אחרי ה‑clamp) שניהם גלויים בתוצאה — חשוב לתצוגה, כדי
שהמשתמש יראה מתי הוזן ערך קיצוני.

## Method A — Lynch / PEG

```
FairValue = EPS(ttm) × growthRatePercentClamped
```

**ללא היוון.** הכי פשוט משתי השיטות. שגיאות אפשריות: `MISSING_EPS`,
`NEGATIVE_OR_ZERO_EPS`, `MISSING_GROWTH_RATE`.

## Method B — Rule #1 (מכפיל יציאה מהוון)

```
epsFuture   = epsTtm × (1 + g)^years
futurePrice = epsFuture × exitPeMultiple
fairValue   = futurePrice / (1 + r)^years
```

כאשר `g = growthRatePercentClamped / 100`, `r = requiredReturnPercent / 100`.

**חשוב:** זו הקרנת EPS יחידה + מכפיל יציאה + היוון פעם אחת — **לא DCF** עם תזרים מזומנים
שנתי מוקרן. `CLAUDE.md`/הקוד עצמם מדגישים את זה במפורש ("still not DCF").

שגיאות נוספות מעבר ל‑Method A: `INVALID_EXIT_PE` (`exitPeMultiple <= 0`),
`INVALID_REQUIRED_RETURN` (`requiredReturnPercent <= 0`), `INVALID_YEARS` (לא שלם חיובי),
`INVALID_MOS` (ראה למטה).

### Margin of Safety (מרווח ביטחון) — נוסף 2026-08-19

פרמטר שישי אופציונלי, `mosPercent` (ברירת מחדל `0`), מהוון את "מחיר המדבקה" (`fairValue`
של Method B) למחיר קנייה יעד:

```
fairValue = stickerPrice × (1 - mosPercent / 100)
```

`calculateRuleOneValue` עצמה מקבלת **כל ערך** ב‑`[0, 100)` — מחוץ לטווח מחזיר
`INVALID_MOS`. **ה‑UI באתר מגביל בפועל לארבעה ערכים בלבד** (0%/10%/25%/50%, ברירת מחדל
25%) דרך `<select>` קבוע — זו מוסכמת ממשק, לא אילוץ שהפונקציה הטהורה או דגל ה‑CLI
(`-m/--mos <percent>`, טקסט חופשי) אוכפים בעצמם.


מוגדרת **בשני המקומות** (`cli/index.ts:41`, `web/public/app.js:290`) ולא בשכבת

יכול לדרוס את הבחירה הזו ידנית.

## `HistoricalPeAverages` — שם מטעה, לתשומת לב

השדות נקראים `avg1y`/`avg3y`/`avg5y` אבל `historicalPe.ts` מחשב **חציון**, לא ממוצע —
מאז `4d54b50`. הסיבה: עם 1–5 נקודות בחלון, שנה חריגה אחת (למשל EPS שקוע זמנית) הייתה
שולטת בממוצע; החציון עמיד יותר, במחיר של לא להיות "ממוצע" פשוטו כמשמעו. כלל הסף:
לפחות `ceil(windowSize / 2)` נקודות תקינות כדי שהחלון לא יהיה `null`.

נקודת P/E אחת לשנת כספים = `close הקרוב-הקודם ביותר / dilutedEps` (EPS לא‑חיובי → נקודה
פסולה, מסוננת החוצה, לא נופלת את כל החלון).

**החלטה פתוחה:** האם לשנות את שמות השדות ל‑`median1y/3y/5y`? נוגע ב‑6+ קבצים כולל ה‑UI.
נדונה ב‑[`TASKS.md`](../TASKS.md) משימה 2 — לא הוכרעה כאן.
