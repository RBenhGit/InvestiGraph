# היסטוריית הערכות ומטמון

← [Home](Home.md)

שני פיצ'רים נפרדים שנוספו יחד בקומיט אחד (2026-08-19), ולכן קל לבלבל ביניהם — אבל הם
עצמאיים לחלוטין זה מזה:

- **`src/data/cache.ts`** — מטמון על הדיסק לתוצאות API (Twelve Data, Yahoo). לא נראה
  למשתמש, שקוף לחלוטין; קיים רק כדי לחסוך קריאות רשת חוזרות ולשרוד נפילת רשת חד־פעמית.
- **`src/history/`** — פיצ'ר גלוי למשתמש: שמירה, צפייה ומחיקה של הערכות שווי שכבר חושבו.

לא לבלבל גם עם הדף [היסטוריה-ומקורות](היסטוריה-ומקורות.md), שעוסק בציר הזמן של
הקומיטים בפרויקט עצמו — שם אחר, נושא אחר לגמרי.

## `src/data/cache.ts` — מטמון שקוף

מבנה: קבצי JSON פשוטים תחת `cache/` בשורש הפרויקט —
`twelvedata_<TICKER>.json` / `yahoo_<TICKER>.json`. תיקייה ניתנת לדריסה דרך משתנה
הסביבה האופציונלי `CACHE_DIR_PATH` (לא ב‑`.env.example` כברירת מחדל פעילה — רק כשורה
מוערת, בדיוק כמו `PORT`).

**זרימת קריאה (`fetchStockData`/`fetchAnalystConsensus`, שתיהן זהות בעיקרון):**

```
1. אם forceRefresh === true  → דלג ישר לשלב 3 (קריאה חיה)
2. אחרת: יש מטמון + גילו < 24h?  → החזר אותו, בלי קריאת רשת בכלל
3. קרא לרשת (Twelve Data / Yahoo)
   ✔ הצליח → שמור למטמון, החזר את התוצאה החדשה
   ✘ נכשל  → יש מטמון (גם ישן)?  → החזר אותו כ‑{ ok: true }, למרות שהוא stale
                אין מטמון כלל?     → החזר { ok: false } (Twelve Data) או null (Yahoo)
```

כשל בכתיבה/קריאה של קובץ המטמון עצמו **נבלע בשקט** — זו החלטת עיצוב מפורשת: כשל
מטמון אף פעם לא אמור להפיל בקשה אמיתית של המשתמש.

**חשוב לזכור:** זה *לא* הופך את הכלי ל"אופליין" באמת. טיקר שמעולם לא נבדק, בלי קובץ
מטמון קיים, עדיין דורש `TWELVE_DATA_API_KEY` חי כדי להחזיר משהו. המטמון פותר שני מקרים
ספציפיים: (1) חוסך קריאות חוזרות למגבלת הקצב כשמשנים הנחות ומריצים שוב אותו טיקר,
(2) שורד הפסקת רשת/API חד־פעמית לטיקר שכבר נבדק קודם.

**עקיפת המטמון:** כפתור "🔄 Refresh Live" באתר, או שדה `forceRefresh: true` ב‑body של
`POST /api/valuate`.

## `src/history/` — שמירת הערכות שווי

מודול חדש תחת `src/`, לא תת־תיקייה של `src/data/`. `index.ts` הוא נקודת הכניסה
היחידה (`saveValuation`, `getHistory`, `deleteValuation`, טיפוסים); `store.ts` פנימי
בלבד (I/O גולמי על `history.json`, נתיב ניתן לדריסה דרך `HISTORY_FILE_PATH`).

אותה מוסכמת `{ ok: boolean }` כמו כל שאר הריפו — `HistoryResult<T>`, `HistoryError`
מסוג `IO_ERROR`/`NOT_FOUND`/`INVALID_INPUT`.

### מה נשמר

כל הערכה שמורה כוללת: טיקר, מחיר, שתי תוצאות ה‑fair value (Lynch + Rule #1), שיעור
הצמיחה שנעשה בו שימוש, ה‑assumptions (מכפיל יציאה/תשואה נדרשת/שנים/MoS), הערות/תזה
חופשיות אופציונליות, וחותמת זמן. רשימה ממוינת מהחדש לישן, עם סינון אופציונלי לפי טיקר.

### חשיפה — כאן אין פער בין ה‑CLI לאתר

בניגוד לפאנל האנליסטים של Yahoo (ראה
[ארכיטקטורה](ארכיטקטורה.md#איפה-המתאמים-באמת-נבדלים-החריג-לרק-קלטפלט)), הפיצ'ר הזה
**חשוף באופן זהה בשני המתאמים**:

| מתאם | איך |
|------|-----|
| Web | `POST /api/valuate` (עם `mosPercent`/`epsOverride` בגוף הבקשה), `GET /api/history?ticker=`, `POST /api/history`, `DELETE /api/history/:id`; כפתור "Save this valuation", טבלת "Saved Valuations" עם סינון/טעינה/מחיקה |
| CLI | `-s, --save` (שמור את התוצאה), `-n, --notes <text>` (תזה חופשית), `-H, --history [ticker]` (הצג היסטוריה שמורה, טבלה מפורמטת בטרמינל) |

## Margin of Safety — קשור, אבל שייך לשכבת ה‑valuation

הפרמטר `mosPercent` שנוסף לאותו קומיט **לא חלק מ‑`src/history/`** — הוא פרמטר בשיטת
Rule #1 עצמה (`src/valuation/ruleOne/`). ראה [שיטות-הערכה](שיטות-הערכה.md#margin-of-safety-מרווח-ביטחון--נוסף-2026-08-19)
לפירוט המלא. מוזכר כאן רק כי ערך ה‑MoS ששימש בהערכה נשמר יחד איתה ב‑`src/history/`
לצורך תצוגה חוזרת.
